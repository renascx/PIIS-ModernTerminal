# Требования

## Цель
Сократить время и число ошибок при настройке сетевого оборудования: LLM предлагает команды,
человек подтверждает, система выполняет и проверяет результат.

## Пользовательские сценарии
1. **Создание VLAN.** «Создай VLAN 20 с именем USERS и назначь на порты Gi0/1–Gi0/4».
   Ассистент показывает набор команд, пользователь подтверждает, команды выполняются.
2. **Port-security.** «Включи port-security на Gi0/5, максимум 2 MAC, действие restrict».
3. **Диагностика.** «Почему порт Gi0/3 не поднимается?» — ассистент читает `show interfaces`
   и объясняет причину (без изменения конфигурации).
4. **Опасная команда.** Модель предложила `reload` — система требует явного подтверждения
   с предупреждением, либо блокирует по политике.

## Функциональные требования
- FR-1. Подключение к устройству по SSH и Telnet.
- FR-2. Чат с ассистентом на базе Ollama, настраиваемые URL и модель.
- FR-3. Ассистент видит последний вывод терминала сессии.
- FR-4. Любая команда, изменяющая конфигурацию, выполняется только после подтверждения.
- FR-5. Опасные команды (reload, erase, format, shutdown и др.) всегда требуют подтверждения.
- FR-6. Журнал аудита: кто, когда, какая команда, подтверждена или отклонена.

## Нефункциональные требования
- Работа с локальной моделью, данные не покидают контур.
- Секреты хранятся в зашифрованном виде.
- Покрытие автотестами ключевой логики (безопасность, цикл агента).

## Метрики успеха
- ≥ 90 % корректных команд на эталонном наборе из 30 сценариев.
- 100 % опасных команд проходят через подтверждение.
- Время настройки типового сценария сокращается минимум вдвое по сравнению с ручным вводом.
