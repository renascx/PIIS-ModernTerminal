# Архитектура

```
Браузер: frontend/ (React + TypeScript + xterm.js)
   │  REST и WebSocket (/api, через прокси Vite)
FastAPI backend (backend/app)
   ├─ main.py             приложение, настройки ИИ, проверка команд
   ├─ routes/
   │   ├─ sessions.py     сессии, вывод терминала, ручные команды
   │   ├─ terminal.py     WebSocket терминала
   │   └─ assistant.py    чат, подтверждение команд, журнал аудита
   ├─ ai/
   │   ├─ base.py             интерфейс AIProvider
   │   ├─ ollama_provider.py  клиент Ollama (/api/chat, /api/tags)
   │   ├─ agent.py            цикл tool-calling и очередь подтверждений
   │   ├─ tools.py            описание инструмента run_command
   │   ├─ prompts.py          системный промпт
   │   └─ safety.py           оценка риска команд
   ├─ connectors/         SSH (asyncssh), Telnet (telnetlib3), буфер вывода
   ├─ session_registry.py связь сессии с коннектором
   └─ audit.py            журнал команд в SQLite
   │
Ollama (локально, http://localhost:11434)

backend/evaluation        оценка качества модели (отдельно от сервера)
   ├─ scenarios.json      32 эталонных сценария
   ├─ mock_device.py      поддельное устройство, отдаёт вывод из сценария
   ├─ scoring.py          правила оценки сценария
   ├─ dataset.py          загрузка и проверка датасета
   └─ runner.py           запуск агента на сценариях и отчёт

backend/Dockerfile          сборка frontend и backend в один образ
backend/docker-compose.yml  backend, Prometheus и Grafana
backend/monitoring/         настройки Prometheus и Grafana (источник данных, дашборд)
.github/workflows/ci.yml    CI: тесты backend и frontend, сборка образа
```

## Мониторинг
Backend отдаёт метрики на `/metrics`: число команд по уровню риска, решению и источнику
(`piis_commands_total`), число открытых сессий (`piis_sessions_active`) и время HTTP-запросов
(`piis_http_request_seconds`). Prometheus собирает их раз в 15 секунд, Grafana показывает готовый дашборд.

## Раздача frontend
В Docker образ собирает frontend на Node и кладёт результат в `/app/static`. Если задана
переменная `STATIC_DIR`, backend отдаёт эти файлы на `/`, поэтому отдельный веб-сервер не нужен.
При разработке интерфейс запускают отдельно (`npm run dev`), Vite проксирует `/api` на backend.

## Frontend
- Форма подключения и список сессий.
- Терминал на xterm.js через WebSocket. Ввод пользователя уходит в сессию как есть.
- Чат ассистента с карточкой подтверждения: команда, уровень риска, кнопки «Выполнить» и «Отклонить».
- Вкладка «Журнал» и переключатель режима подтверждения.

## Как проходит команда ассистента
1. Пользователь пишет в чат, к сообщению добавляется последний вывод терминала.
2. Модель отвечает текстом или вызывает `run_command`.
3. Команда проходит `safety.assess`. Если в текущем режиме нужно подтверждение,
   она ждёт в очереди `pending`; опасные команды ждут всегда.
4. Пользователь подтверждает или отклоняет, результат и вывод уходят обратно модели.
5. Каждое решение записывается в журнал аудита.

## Как работает оценка
Раннер создаёт для сценария поддельное устройство, запускает того же агента, что и сервер,
и сам отвечает на запросы подтверждения по правилам сценария. Затем `scoring.py` проверяет,
что нужные команды найдены, запрещённые не отправлялись, а после отказа опасная команда
не повторялась. С флагом `--fake` вместо модели используется заглушка, которая отправляет
ожидаемые команды: так проверяется сам скрипт.

## Принципы
- Провайдер ИИ подменяемый: агент зависит только от `AIProvider`.
- Режим `confirm` подтверждает все команды, `readonly_auto` пропускает только `show` и `ping`.
- История чата хранится в памяти, журнал аудита — в SQLite.
